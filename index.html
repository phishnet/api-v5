Phish.net API v5

An example suite for fetching and displaying Phish.net data

This repo is a from-scratch set of examples showing how to call the Phish.net API v5 from plain HTML and JavaScript — no framework, no build tooling, no npm dependencies. Each page below is a self-contained, working demo.

Setup

  1. Request a free API key at phish.net/api/keys.
  2. Copy scripts/apikey.example.js to scripts/apikey.js and paste in your key.
  3. Run node server.js (or npm start), then open http://localhost:8000.

This needs Node installed, but nothing else — server.js has zero dependencies, so there's no npm install step.

How it works

Every page loads two shared, dependency-free scripts from scripts/:

  • phishnet-client.js — a small client with one function, PhishNet.phishnet(path, params), that fetch()es the API (through the local proxy) and returns its data array (or throws with a readable message on error).
  • setlist-format.js — shared HTML rendering for setlists, used by both the Latest Setlist and Setlist Browser examples.

Why this needs a local server at all: api.phish.net does not send Access-Control-Allow-Origin headers, so a cross-origin fetch() straight from a page on a different origin is blocked before the response body can be read. The API's own documented workaround for this — a callback parameter for JSONP — turns out not to work in a modern browser either: its callback-wrapped response is still served as Content-Type: application/json with X-Content-Type-Options: nosniff, which Chrome, Firefox, and Safari all refuse to execute as a <script> (confirmed against the live API). server.js serves these static files and proxies /api/* requests to api.phish.net server-side, where neither restriction applies — so the browser code is just plain fetch(), and your API key never has to leave the server.
